# dispatch-orchestrator — runbook (le cœur de la forge, Phase C : la boucle enchaîne dispatch → gate → merge-ready, feature-groupe-de-tasks)

`orchestrator.py` porte la boucle de forge de `cockpit run <project>`. L'unité n'est pas la task mais la **feature** — un groupe de tasks séquentielles = une branche = un worktree = un **mutex** (un seul worker à la fois). La boucle draine la roadmap : elle découvre les features prêtes, en dispatche jusqu'à `max_parallel` en parallèle, avance le DAG intra-feature au fil des succès (task → `done`), puis finalise chaque feature au travail complet (Tier-0 + reviewer → merge-ready). Invariant cardinal : la boucle produit des commits et un verdict de gate, **jamais un merge** — le GO qui merge/détruit reste un gate humain fail-closed (`human_go=False` en dur).

## run_project() — draine la roadmap, boucle principale
`src/cockpit/dispatch/orchestrator.py:223` · appelé par cli_dispatch (route `cockpit run`) / le daemon
Entrées : `conn` (connexion principale, seule lectrice-assignatrice), `settings`, `project`, `max_parallel` (défaut 2), et les runners injectables (`git`, `runner`, `review_runner`). Comportement : sous un `ThreadPoolExecutor`, boucle infinie — à chaque tour elle demande à `_discoverable_features()` les slugs dispatchables, réserve chacun dans `in_flight` **avant** le `submit` (mutex par feature : jamais deux fois la même en vol), puis `wait(FIRST_COMPLETED)` ; pour chaque future terminée elle retire le slug d'`in_flight`, collecte le rapport et, si `ok` est faux, exclut la feature via `failed` (borne le run, pas de re-dispatch infini). Sortie de boucle quand `pending` est vide (rien en vol ni à soumettre → drainé). Puis, drain fini, elle finalise chaque feature complète (`_worked_complete_features` → `_finalize_feature`) et rend le rapport agrégé de `_summarize`. Invariant de terminaison : chaque run fini fait progresser une task (`done`) OU exclut sa feature (`failed`) → le travail restant décroît strictement. Le merge n'est PAS ici — la boucle s'arrête à merge-ready.

## _dispatch_one() — dispatche la NEXT task d'une feature, dans son thread
`src/cockpit/dispatch/orchestrator.py:116` · appelé par run_project (via `pool.submit`, un thread par feature en vol)
Entrées : `settings`, `project`, `feature`, `git`, `runner`. Comportement : ouvre une **connexion propre au thread** (`store.connect`, `check_same_thread` — concurrence SQLite absorbée par le `busy_timeout` posé à la connexion), délègue à `worker.dispatch_next` sur `feature_ref = project/feature`. Sur succès (`report.dispatched` ET `result.ok`), la boucle **possède la transition de clôture** : `dispatch_next` laisse la task `in_progress` (le `done` est déféré au merge en mode mono) — ici elle passe la task à `done` par un `UPDATE tasks` puis `commit`. Sortie : rapport `{feature, task, ok, reason}`, **jamais une exception** vers la boucle (un worker échoue, il ne plante pas). Sémantique : task `done` = worker OK + commit posé ; le merge de la feature reste un gate humain séparé. Appelé exclusivement depuis les threads de `run_project`.

## _discoverable_features() — sélectionne et priorise les features dispatchables
`src/cockpit/dispatch/orchestrator.py:90` · appelé par run_project (une fois par tour de boucle)
Read-only sur la connexion principale. Entrées : `conn`, `project`, `in_flight`, `failed`. Comportement : calcule une fois par passe le DAG **inter-feature** (`resolver.classify_features`, deps v10), puis pour chaque feature écarte celles qui sont inertes (`merged`/`cancelled`), en vol, en échec, ou dont l'état inter-feature est bloqué (`BLOCKED_DEPS`/`ERROR`/`CYCLE` — prérequis non `merged`, ou graphe malformé) ; charge l'index intra-feature (`index_for_feature`) et n'admet la feature que si `resolve_next` expose une NEXT task READY. Sortie : slugs triés par `(priorité, created_at, slug)` → les priorités hautes soumises d'abord. Invariant : une feature n'est dispatchable que si toutes ses prérequises sont `merged` (le cas design→code est enforcé, plus « résolu à la main par l'ordre de merge »).

## _worked_complete_features() — les features dont le travail est fini
`src/cockpit/dispatch/orchestrator.py:147` · appelé par run_project (une fois, après le drain)
Read-only. Entrées : `conn`, `project`, `failed`. Comportement : retient les features encore `active` (ni `merged` ni `cancelled`), non en échec, dont **toutes** les tasks sont `done`/`cancelled` avec **au moins une** `done` (≥1 task réellement travaillée). Sortie : liste de slugs prêts à la finalisation (Tier-0 + review → merge-ready). Invariant : merge à feature **complète** — on ne finalise jamais une feature partielle. C'est la porte d'entrée du tronçon qualité de la boucle.

## _finalize_feature() — Tier-0 + reviewer → verdict de gate en preview
`src/cockpit/dispatch/orchestrator.py:116` · appelé par run_project (une par feature complète)
Entrées : `conn`, `settings`, `project`, `feature`, `review_runner`. Comportement : résout la feature, calcule le **SHA de HEAD** de sa branche (`git.feature_sha`) et le diff vs `_BASE_BRANCH = "dev"` (fraîcheur liée au SHA — si la branche est absente, jamais dispatchée, retourne un blocker propre) ; si le worktree existe, exécute le **Tier-0 toolchain** (déterministe, SHA-bound) et écrit son verdict ; dispatche le **reviewer Tier-1** (charte : LLM génère / déterministe gate) ; évalue le gate en **preview `human_go=False`** — on ne merge JAMAIS ici. Sortie : `{feature, merge_ready, blockers, review}` où `merge_ready` reflète `gate_green`. Best-effort : une pièce en échec laisse le gate bloquer proprement et le blocker est surfacé. Invariant fail-closed : cette fonction est le mur entre l'autonomie (produire un verdict) et l'action destructrice (merge/destroy), qui exige le GO humain séparé (`cockpit merge --go`).

## Zones non détaillées
- `_summarize` (`orchestrator.py:185`) — helper de formatage : agrège runs + finalisations en rapport (`dispatched`/`ok`/`failed`/`drained`/`merge_ready`) ; `drained ⟺ aucune feature en échec`. Pas de logique de boucle.
- `cli_dispatch` (`orchestrator.py:200`) — route CLI `cockpit run <project> [--max-parallel N]` : **gate d'auth fail-closed** (refuse avant tout spawn si pas d'auth Claude explicite, exit 2), appelle `run_project`, imprime le rapport et les lignes merge-ready (`✅` avec la commande `cockpit merge … --go`, `🟡` sinon). Exit 0 si drainée sans échec, 1 sinon.
